4. 집계 연산 선택과 사용

집계는 여러 기록을 하나의 값으로 요약하는 계산입니다. 예를 들어 10, 20, 30을 합계로 계산하면 60, 평균으로 계산하면 20입니다. 피벗의 각 셀은 행과 열 조건에 해당하는 기록을 모아 선택한 방식으로 계산합니다.

AUIPivot은 17개 내장 연산을 제공합니다. 원하는 연산을 setValueFields()의 operation에 지정합니다. 직접 만든 계산 방법은 registerCustomAggregator()로 등록할 수 있습니다.

4.1 연산을 지정하는 방법

dataField에는 계산할 필드 이름, operation에는 연산 이름을 지정합니다. 아래 예제의 VALUE는 설명용 필드 이름입니다. 실제 데이터의 가격, 수량, 점수 등 계산하려는 필드 이름으로 바꿔 사용하세요.

// 같은 필드의 합계와 평균을 나란히 표시합니다.
AUIPivot.setValueFields(pid, [
  {dataField: "VALUE", operation: "SUM", customLabelText: "합계"},
  {dataField: "VALUE", operation: "AVG", customLabelText: "평균", formatString: "#,##0.00"}
]);

현재 보고서의 설정을 바꾼 뒤에는 updatePivot()으로 다시 계산합니다. 처음 데이터를 넣을 때는 setGridData()가 계산을 시작합니다.

customLabelText는 제목, formatString은 숫자의 표시 형식입니다. 예를 들어 0.00%는 계산값 0.25를 25.00%로 표시합니다. 표시 형식을 바꿔도 실제 계산값은 바뀌지 않습니다. 같은 필드에 같은 연산을 제목만 달리하여 중복 배치할 수는 없습니다.

아래 설명은 작은 숫자로 계산 방법을 보여 줍니다. 각 절의 자동차 판매 데모에서는 같은 연산을 실제 데이터에 적용한 모습을 볼 수 있습니다.

4.2 SUM — 합계

값을 모두 더합니다.

계산 예: 10, 20, 30의 합계는 10 + 20 + 30 = 60입니다.

// VALUE 필드의 값을 모두 더합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "SUM", formatString: "#,##0"}]);

주의: 수량 필드에 SUM을 지정하면 수량의 합계를 구합니다. 기록이 몇 건인지를 세려면 COUNT를 사용합니다.

자동차 판매 데모, setValueFields()

4.3 COUNT — 개수

지정한 필드에서 빈 값이 아닌 값의 개수를 셉니다. 값이 같아도 각 기록을 따로 셉니다.

계산 예: 10, 10, 30은 3개입니다. 10, null, 30은 null을 제외하여 2개입니다.

// VALUE 필드에 값이 있는 기록의 개수를 셉니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "COUNT", formatString: "#,##0"}]);

주의: null, undefined, 빈 문자열은 제외합니다. 모든 기록을 세려면 모든 기록에 값이 있는 필드를 선택하세요. 수량이 2와 3인 두 기록의 COUNT는 2, SUM은 5입니다. 숫자만 세는 연산은 아니며 자료형별 처리 차이는 입력값 처리를 참고하세요.

자동차 판매 데모, setValueFields()

4.4 DISTINCT_COUNT — 중복을 제외한 개수

같은 값이 여러 번 나타나도 한 번만 셉니다.

계산 예: A, A, B, C는 A, B, C로 구분되므로 3개입니다. COUNT를 사용하면 4개입니다.

// VALUE 필드에서 서로 다른 값이 몇 개인지 셉니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "DISTINCT_COUNT", formatString: "#,##0"}]);

주의: null, undefined, 빈 문자열은 제외합니다. 전체 개수도 원본에서 중복을 다시 제거하여 계산합니다. A, B가 있는 그룹과 B, C가 있는 그룹의 전체 고유 개수는 4가 아니라 3입니다.

자동차 판매 데모, setValueFields()

4.5 MIN — 최솟값

가장 작은 값을 찾습니다.

계산 예: 30, 10, 20의 최솟값은 10입니다.

// VALUE 필드에서 가장 작은 값을 찾습니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "MIN", formatString: "#,##0"}]);

주의: 원본 순서와 관계없이 숫자의 크기로 비교합니다. null이나 빈 문자열은 숫자 변환 시 0이 될 수 있으므로, 값이 없다는 뜻으로 넣은 데이터가 있다면 입력값 처리도 확인하세요.

자동차 판매 데모, setValueFields()

4.6 MAX — 최댓값

가장 큰 값을 찾습니다.

계산 예: 30, 10, 20의 최댓값은 30입니다.

// VALUE 필드에서 가장 큰 값을 찾습니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "MAX", formatString: "#,##0"}]);

주의: MIN과 함께 사용하면 값의 범위를 볼 수 있습니다. 숫자 변환 방식은 MIN과 같습니다.

자동차 판매 데모, setValueFields()

4.7 AVG — 산술 평균

합계를 개수로 나눕니다. 각 기록을 같은 비중으로 계산하는 일반적인 평균입니다.

계산 예: 10, 20, 30의 평균은 (10 + 20 + 30) / 3 = 20입니다.

// VALUE 필드의 합계를 개수로 나눕니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "AVG", formatString: "#,##0.00"}]);

주의: 별도 수량 필드가 있어도 자동으로 반영하지 않습니다. 수량을 반영한 평균이 필요하면 RATIO_OF_SUMS의 예를 참고하세요. AVG는 SUM과 COUNT를 사용하므로 숫자가 아닌 값이 섞이면 원하는 평균과 달라질 수 있습니다.

자동차 판매 데모, setValueFields()

4.8 MEDIAN — 중앙값

값을 작은 순서로 늘어놓았을 때 가운데에 있는 값입니다. 개수가 짝수이면 가운데 두 값의 평균을 구합니다.

계산 예: 10, 20, 100의 중앙값은 20입니다. 10, 20, 30, 500의 중앙값은 (20 + 30) / 2 = 25입니다. 뒤의 예에서 산술 평균은 140이므로 큰 값 하나에 영향을 받는 정도가 다릅니다.

// VALUE 필드를 숫자 순서로 정렬했을 때의 가운데 값을 구합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "MEDIAN", formatString: "#,##0.00"}]);

주의: 소계와 총계도 해당 원본 값들을 모아서 중앙값을 구합니다. 하위 셀의 중앙값들을 평균내지 않습니다. 계산할 숫자가 없으면 빈 값입니다. 숫자를 모아 정렬하므로 SUM보다 메모리와 계산 시간이 더 필요합니다.

자동차 판매 데모, setValueFields()

4.9 MULTIPLY — 곱

같은 필드의 값들을 차례로 곱합니다.

계산 예: 2, 3, 4의 곱은 2 × 3 × 4 = 24입니다.

// 각 기록에 있는 VALUE 값을 서로 곱합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "MULTIPLY", formatString: "#,##0"}]);

주의: 한 기록의 가격과 수량을 곱하는 기능과는 다릅니다. 기록마다 두 필드를 곱해 새 필드를 만들려면 setDerivedFields()를 사용합니다. 0이 포함되면 곱은 0이 되며, null이나 빈 문자열도 숫자 변환 시 0이 됩니다.

자동차 판매 데모, setValueFields()

4.10 비율은 무엇으로 나누는지가 다릅니다

다음은 한 필드의 합계로 만든 표입니다. A행, X열의 값 10을 기준으로 세 연산을 비교해 보세요.

구분X열Y열행 합계
A행102030
B행304070
열 합계4060전체 100
연산나누는 기준A행, X열 결과
RATIOX열의 합계 4010 / 40 = 25%
ROW_RATIOA행의 합계 3010 / 30 ≈ 33.33%
GRAND_TOTAL_RATIO표 전체의 합계 10010 / 100 = 10%

합계 대신 개수로 전체 대비 비율을 구하려면 GRAND_TOTAL_COUNT_RATIO, 서로 다른 두 필드의 합계를 나누려면 RATIO_OF_SUMS를 사용합니다.

여기서 ‘전체’는 현재 필터 조건에 포함된 데이터 전체입니다. 필터를 적용하면 나누는 기준도 다시 계산됩니다. 여러 값 필드를 표시하더라도 다른 필드의 합계와 섞지 않습니다.

4.11 RATIO — 열 합계 대비 비율

현재 셀의 합계를 같은 열의 전체 합계로 나눕니다.

계산 예: 위 표에서 A행, X열은 10 / 40 = 25%입니다. B행, X열은 30 / 40 = 75%입니다.

// 같은 열의 합계를 기준으로 각 셀의 비율을 표시합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "RATIO", formatString: "0.00%"}]);

주의: X열은 40, Y열은 60으로 나눕니다. 열이 바뀌면 기준 합계도 달라집니다. 표 전체의 합계 100으로 나누려면 GRAND_TOTAL_RATIO를 사용합니다.

자동차 판매 데모, setValueFields()

4.12 ROW_RATIO — 행 합계 대비 비율

현재 셀의 합계를 같은 행의 전체 합계로 나눕니다.

계산 예: 위 표에서 A행, X열은 10 / 30 ≈ 33.33%입니다. A행, Y열은 20 / 30 ≈ 66.67%입니다.

// 같은 행의 합계를 기준으로 각 셀의 비율을 표시합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "ROW_RATIO", formatString: "0.00%"}]);

주의: A행은 30, B행은 70으로 나눕니다. 행이 바뀌면 기준 합계도 달라집니다.

자동차 판매 데모, setValueFields()

4.13 GRAND_TOTAL_RATIO — 전체 합계 대비 비율

현재 셀의 합계를 보고서 전체의 합계로 나눕니다. 전체에서 각 부분이 차지하는 비율을 구할 때 사용합니다.

계산 예: 위 표에서 A행, X열은 10 / 100 = 10%입니다. A행 전체는 30 / 100 = 30%, 총계는 100%입니다.

// 보고서 전체의 VALUE 합계를 기준으로 비율을 표시합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "GRAND_TOTAL_RATIO", formatString: "0.00%"}]);

주의: 각 셀과 소계가 같은 전체 합계로 나눕니다. 필터를 적용하면 분자와 분모 모두 필터에 포함된 데이터로 다시 계산됩니다. 분모가 0이거나 유한한 비율을 구할 수 없으면 빈 값입니다. 음수가 포함되면 비율도 음수이거나 100%를 넘을 수 있습니다.

자동차 판매 데모, setValueFields()

4.14 GRAND_TOTAL_COUNT_RATIO — 전체 개수 대비 비율

현재 셀에서 센 개수를 보고서 전체에서 센 개수로 나눕니다. 개수는 같은 필드의 COUNT 방식으로 셉니다.

계산 예: 전체에서 센 값이 10개이고 그중 A그룹에 3개가 있으면 3 / 10 = 30%입니다.

// VALUE 값의 전체 개수 중 각 셀이 차지하는 비율을 표시합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "GRAND_TOTAL_COUNT_RATIO", formatString: "0.00%"}]);

주의: 값의 합계나 중복을 제외한 개수로 계산하지 않습니다. 수량 필드를 지정해도 수량 합계의 비율이 되지는 않습니다. 빈 값의 제외 기준은 COUNT와 같으며, 필터를 적용하면 전체 개수도 바뀝니다. 전체 개수가 0이면 빈 값입니다.

자동차 판매 데모, setValueFields()

4.15 RATIO_OF_SUMS — 두 합계의 비율

같은 그룹 안에서 첫 번째 필드의 합계를 두 번째 필드의 합계로 나눕니다. numeratorField는 분자 필드, denominatorField는 분모 필드입니다.

계산 예: 분자 값이 100, 900이고 분모 값이 2, 3이면 (100 + 900) / (2 + 3) = 200입니다. 각 기록을 먼저 나눈 50과 300의 평균 175와는 다릅니다.

// AMOUNT의 합계를 QUANTITY의 합계로 나눕니다.
AUIPivot.setValueFields(pid, [{
  dataField: "AMOUNT",
  operation: "RATIO_OF_SUMS",
  numeratorField: "AMOUNT",    // 분자로 사용할 필드입니다.
  denominatorField: "QUANTITY", // 분모로 사용할 필드입니다.
  customLabelText: "두 합계의 비율",
  formatString: "#,##0.00"
}]);

주의: denominatorField는 반드시 지정합니다. numeratorField를 생략하면 dataField를 분자로 사용합니다. 필요한 필드가 없거나 분모 합계가 0이면 빈 값입니다. 소계와 총계도 각 범위의 두 합계를 구한 뒤 나누며, 하위 비율들을 평균내지 않습니다.

4.15.1 가중 평균과는 어떤 관계인가요?

이 연산 자체의 뜻은 ‘두 합계의 비율’입니다. 무엇을 합하여 나누는지에 따라 결과의 의미가 달라집니다.

예를 들어 금액이 단가 × 수량이라면, 금액 합계 / 수량 합계로 수량을 반영한 평균 단가를 구할 수 있습니다. 이것이 수량을 가중치로 사용한 가중 평균입니다. 100원짜리 1개와 300원짜리 3개라면 물건 네 개의 가격은 100, 300, 300, 300원입니다. 평균은 1,000 / 4 = 250원입니다.

자동차 판매 데이터에서는 AMOUNT 대신 TOTAL, QUANTITY 대신 COUNT를 사용하면 같은 방식으로 대당 매출을 구할 수 있습니다. 백분율로 보여 줄 값이라면 formatString을 0.00%로 지정하세요.

자동차 판매 데모, setValueFields()

4.16 분산과 표준편차를 고르는 방법

둘 다 값들이 평균 주변에 얼마나 흩어져 있는지 나타냅니다. 값들이 비슷하면 작고, 차이가 크면 커집니다. 모든 값이 같으면 0입니다.

  • 모집단: 알고 싶은 대상 전체를 계산합니다. VARIANCE, STD_DEVIATION을 사용합니다.
  • 표본: 대상 전체 중 일부 자료로 전체의 흩어짐을 추정합니다. SAMPLE_VARIANCE, SAMPLE_STD_DEVIATION을 사용합니다.

자료가 많고 적음에 따라 구분하는 것이 아닙니다. 필터로 고른 자료 자체를 전체 분석 대상으로 삼을 수도 있고, 더 큰 대상의 일부 표본으로 볼 수도 있습니다.

아래 네 연산은 모두 2, 4, 6을 예로 사용합니다. 평균은 4이며, 평균과의 차이는 -2, 0, 2입니다. 차이를 제곱하여 더하면 4 + 0 + 4 = 8입니다.

연산계산결과
VARIANCE8 / 3약 2.67
STD_DEVIATION8 / 3의 제곱근약 1.63
SAMPLE_VARIANCE8 / (3 - 1)4
SAMPLE_STD_DEVIATION4의 제곱근2

4.17 VARIANCE — 모집단 분산

각 값이 평균에서 떨어진 거리를 제곱하여 더한 뒤, 값의 개수로 나눕니다.

계산 예: 2, 4, 6의 평균은 4입니다. ((2 - 4)² + (4 - 4)² + (6 - 4)²) / 3 = 8 / 3 ≈ 2.67입니다.

// VALUE의 모든 값을 분석 대상 전체로 보고 분산을 구합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "VARIANCE", formatString: "#,##0.00"}]);

주의: 분산의 단위는 원래 값의 단위를 제곱한 것입니다. 원래 단위로 흩어짐을 읽고 싶다면 STD_DEVIATION을 사용합니다. 숫자 하나만 있으면 분산은 0입니다.

자동차 판매 데모, setValueFields()

4.18 STD_DEVIATION — 모집단 표준편차

모집단 분산의 제곱근입니다. 값들이 흩어진 정도를 원래 값과 같은 단위로 표현합니다.

계산 예: 2, 4, 6의 분산은 8 / 3이므로 표준편차는 √(8 / 3) ≈ 1.63입니다. 점수를 계산했다면 표준편차의 단위도 점입니다.

// 모집단 분산의 제곱근을 구합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "STD_DEVIATION", formatString: "#,##0.00"}]);

주의: VARIANCE와 같은 자료를 사용하되 결과의 단위가 다릅니다. 값이 하나이거나 모두 같으면 0입니다.

자동차 판매 데모, setValueFields()

4.19 SAMPLE_VARIANCE — 표본 분산

평균과의 차이를 제곱하여 더한 뒤, 개수에서 1을 뺀 값으로 나눕니다. 일부 자료로 전체의 흩어짐을 추정할 때 사용합니다.

계산 예: 2, 4, 6에서는 8 / (3 - 1) = 4입니다. 같은 자료의 모집단 분산 8 / 3보다 큽니다.

// VALUE를 더 큰 대상에서 뽑은 표본으로 보고 분산을 구합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "SAMPLE_VARIANCE", formatString: "#,##0.00"}]);

주의: 계산에 포함되는 값이 2개보다 적으면 빈 값입니다. 같은 값이 2개 이상이면 0입니다. 소계와 총계는 각 범위의 원본으로 다시 계산합니다.

자동차 판매 데모, setValueFields()

4.20 SAMPLE_STD_DEVIATION — 표본 표준편차

표본 분산의 제곱근입니다. 표본으로 추정한 흩어짐을 원래 값과 같은 단위로 표현합니다.

계산 예: 2, 4, 6의 표본 분산은 4이므로 표본 표준편차는 √4 = 2입니다.

// 표본 분산의 제곱근을 구합니다.
AUIPivot.setValueFields(pid, [{dataField: "VALUE", operation: "SAMPLE_STD_DEVIATION", formatString: "#,##0.00"}]);

주의: SAMPLE_VARIANCE와 마찬가지로 값이 2개 이상 있어야 계산할 수 있습니다. 대상 전체의 표준편차를 구하려면 STD_DEVIATION을 사용합니다.

자동차 판매 데모, setValueFields()

4.21 소계, 총계와 필터는 어떻게 반영되나요?

소계와 총계는 그 범위에 포함된 원본 기록을 기준으로 계산합니다. 화면에 있는 하위 셀들을 무조건 더하거나 평균내는 것이 아닙니다.

예를 들어 한 그룹의 값이 10이고 다른 그룹의 값이 20, 30이면 전체 평균은 (10 + 20 + 30) / 3 = 20입니다. 두 그룹의 평균 10과 25를 다시 평균낸 17.5가 아닙니다. 중복을 제외한 개수, 중앙값, 분산과 비율도 각 연산의 계산 방식을 따릅니다.

필터를 바꾸면 계산에 포함되는 원본이 달라집니다. 정렬이나 접기, 펼치기는 원본의 포함 여부를 바꾸지 않습니다. 총계 행이나 열을 화면에서 숨겨도 전체 비율을 계산하는 기준은 유지됩니다.

열, 행, 전체 비율 비교 데모

4.22 빈 값과 숫자가 아닌 값의 처리

위 숫자 예제는 모두 일반적인 숫자를 사용했습니다. 실제 데이터에 빈 값이나 문자열이 섞이면 연산에 따라 처리 방법이 다릅니다. 특히 화면의 빈 칸과 숫자 0은 다릅니다.

자료형별 처리와 계산할 수 없는 경우 자세히 보기
  • SUM, MIN, MAX, MULTIPLY: JavaScript의 Number()로 변환하여 계산합니다. 숫자 문자열은 숫자로, null과 빈 문자열은 0으로 바뀝니다. 변환 결과가 NaN이면 숫자 계산에서 제외합니다. Infinity처럼 유한하지 않은 값이나 지나치게 큰 곱은 정상적인 숫자 결과를 만들지 못할 수 있습니다.
  • COUNT, AVG와 분산 연산: COUNT는 null, undefined, 빈 문자열을 제외하지만 숫자가 아닌 문자열도 셀 수 있습니다. false와 일부 특수값은 값 필드를 하나 또는 여러 개 배치했을 때 개수 판정에 차이가 있습니다. AVG는 SUM / COUNT이며, 분산 연산도 이 개수 판정을 사용합니다. 예를 들어 개수에 포함되는 비숫자 문자열은 통계 누적에서 0으로 처리될 수 있으므로, 숫자 집계를 할 필드는 숫자형으로 일관되게 준비하세요.
  • DISTINCT_COUNT: null, undefined, 빈 문자열을 제외하고 0과 false는 포함합니다. 숫자 1과 문자열 "1"은 서로 다른 값입니다. NaN은 하나로 세며 +0과 -0은 같습니다. 객체와 Date는 내용이 같아도 서로 다른 객체이면 다르게 셉니다. 날짜나 식별자는 일정한 문자열 형태로 준비하면 의도한 중복을 구분하기 쉽습니다.
  • MEDIAN: null, undefined, 빈 문자열을 먼저 제외합니다. 나머지는 Number()로 변환하고 유한한 숫자만 사용합니다. 숫자 문자열, 참과 거짓 값, Date도 숫자로 변환될 수 있습니다.
  • RATIO_OF_SUMS: 분자와 분모를 각각 숫자로 변환하여 합산합니다. 한 기록에서 한쪽 값이 숫자가 아니어도 반대쪽의 정상 값은 자기 합계에 포함됩니다. 분모가 0이거나 필요한 필드가 없거나 유한한 비율을 구할 수 없으면 빈 값입니다.
  • 비율의 0 분모: GRAND_TOTAL_RATIO, GRAND_TOTAL_COUNT_RATIO는 빈 값을 반환합니다. 기존 RATIO, ROW_RATIO는 셀에서 NaN이나 Infinity가 나올 수 있어 같은 처리라고 가정하면 안 됩니다.
  • 분산과 표준편차: 숫자가 매우 커도 오차를 줄이도록 누적 계산합니다. 예를 들어 10¹² + 1, 10¹² + 2, 10¹² + 3의 모집단 분산은 2 / 3, 표본 분산은 1입니다. 계산 가능한 개수가 부족하거나 유한한 결과를 구할 수 없는 경우는 빈 값입니다.

4.23 사용자 정의 집계 — 직접 정한 집계 방법

registerCustomAggregator()는 여러 기록을 어떻게 모아 하나의 결과로 계산할지 직접 작성하여 등록하는 메소드입니다. 등록할 때 정한 ID를 setValueFields()의 operation에 지정하면 내장 연산처럼 사용할 수 있습니다.

예를 들어 조건을 만족하는 수량의 비율, 중복 고객을 고려한 고객당 평균 등을 만들 수 있습니다. 기존 내장 연산으로 계산할 수 있으면 해당 연산을 사용하고, 별도 조건이나 계산 절차가 필요할 때 사용자 정의 집계를 사용하세요. setDerivedFields()는 기록마다 새 필드를 만드는 메소드이며, 여러 기록을 모아 계산하는 집계와 역할이 다릅니다.

4.23.1 네 함수로 계산 방법을 작성합니다

계산 도중 모아 둘 값들을 state 객체에 담습니다. 다음 네 함수가 필요합니다.

함수작성할 내용
create(context)합계 등을 담을 새 state 객체를 만듭니다. 계산 영역마다 별도 객체를 반환합니다.
accumulate(state, value, context)원본 기록 한 건을 읽어 state에 더합니다. value는 지정한 dataField의 값입니다.
merge(target, source, context)두 영역에서 모은 state를 합칩니다. target에 더하고 source는 변경하지 않습니다.
finalize(state, context)state로 최종 숫자를 구해 반환합니다. state는 변경하지 않습니다.

4.23.2 예: 수량을 반영한 평균 가격

100원짜리 1개와 300원짜리 3개를 계산해 보겠습니다. 물건 네 개의 가격을 풀어 쓰면 100, 300, 300, 300원입니다.

기록가격 PRICE수량 COUNT가격 × 수량
A1001100
B3003900

전체 금액은 1,000원, 수량은 4개이므로 개당 평균은 250원입니다. PRICE의 두 값만 AVG로 계산하면 (100 + 300) / 2 = 200원입니다. 수량을 반영한 250원이 이 예제의 가중 평균입니다.

COUNT는 여기서 수량을 담은 필드 이름입니다. 개수를 세는 COUNT 연산과 구분하세요. 금액 필드가 이미 있다면 RATIO_OF_SUMS로 계산할 수 있습니다. 아래 코드는 가격 × 수량을 직접 누적하며 사용할 기록의 조건도 지정하는 예입니다.

// 수량을 반영한 평균 가격의 계산 방법을 등록합니다.
const weightedPrice = AUIPivot.registerCustomAggregator(pid, {
  id: "WEIGHTED_PRICE", // 코드에서 사용할 고유한 연산 이름입니다.
  version: 1, // 이 계산 정의의 버전이며 제품 버전과는 다릅니다.
  labelText: "수량을 반영한 평균 가격",
  defaultOptions: {weightField: "COUNT"}, // 수량을 읽을 필드입니다.
  validateOptions(options, context) {
    // 이 집계에 필요한 보조 필드를 선언합니다.
    if (typeof options.weightField !== "string") return false;
    context.requireField(options.weightField);
  },
  create(context) {
    // 각 계산 영역의 금액 합계와 수량 합계를 담습니다.
    return {amount: 0, units: 0};
  },
  accumulate(state, value, context) {
    // value는 현재 기록의 PRICE이며, 같은 기록의 수량도 읽습니다.
    const units = context.getValue(context.options.weightField);
    // 이 예제에서는 숫자인 가격과 0보다 큰 숫자 수량만 사용합니다.
    if (typeof value === "number" && Number.isFinite(value) &&
        typeof units === "number" && Number.isFinite(units) && units > 0) {
      state.amount += value * units;
      state.units += units;
    }
  },
  merge(target, source, context) {
    // 다른 영역에서 구한 금액 합계와 수량 합계를 각각 더합니다.
    target.amount += source.amount;
    target.units += source.units;
  },
  finalize(state, context) {
    // 금액 1,000을 수량 4로 나누면 250입니다. 수량이 없으면 빈 값입니다.
    return state.units > 0 ? state.amount / state.units : null;
  }
});
// 등록한 연산을 일반 평균과 나란히 배치합니다.
AUIPivot.setValueFields(pid, [
  {dataField: "PRICE", operation: "AVG", customLabelText: "일반 평균"},
  {dataField: "PRICE", operation: weightedPrice, formatString: "#,##0.00"}
]);
// 계산을 눈으로 확인하기 위한 작은 고정 예제입니다.
AUIPivot.setGridData(pid, [
  {PRICE: 100, COUNT: 1},
  {PRICE: 300, COUNT: 3}
]);
// 결과: 일반 평균 200, 수량을 반영한 평균 가격 250.00

첫 기록을 읽으면 state는 {amount: 100, units: 1}, 두 번째 기록까지 읽으면 {amount: 1000, units: 4}가 됩니다. finalize()가 1000 / 4를 계산합니다. 소계와 총계에서도 평균들을 다시 평균내지 않고, 금액과 수량을 각각 합친 뒤 나눕니다.

등록 옵션과 보고서 저장, 복원 자세히 보기
  • id는 내장 연산이나 같은 피벗에 등록한 이름과 겹칠 수 없습니다. 메소드는 이 연산 ID를 반환합니다. labelText는 필드 패널의 연산 목록에 표시할 이름입니다.
  • defaultOptions는 기본 설정입니다. 값 필드에 aggregatorOptions를 지정하면 그 객체를 사용하며 기본 객체와 합치지 않습니다. weightField는 이 예제에서 직접 정한 옵션 이름입니다.
  • validateOptions(options, context)는 선택 함수입니다. 잘못된 옵션은 false를 반환하거나 오류를 발생시켜 거부합니다. context.requireField()는 계산에 필요한 보조 필드를 선언합니다. 이 context에는 dataField, operation, requireField가 제공되며 등록 시점에는 dataField가 빈 문자열일 수 있습니다.
  • 네 계산 함수의 context에는 dataField, operation, options, getValue가 제공됩니다. getValue()는 accumulate 안에서만 사용할 수 있으며 원본 필드와 등록된 파생 필드를 읽습니다. 함수들은 동기 함수로 작성하고 누적, 병합 순서가 달라도 같은 계산 의미가 되게 합니다.
  • getCustomAggregators()는 ID, 버전, 표시 이름을 조회합니다. 함수나 계산 중 state를 백업하지 않습니다.
  • 보고서에는 집계 ID, 버전과 값 필드의 옵션이 저장됩니다. 다른 피벗에서 복원할 때는 먼저 같은 ID와 버전의 계산 정의를 등록하고 setReportDefinition()을 호출합니다.
  • 콜백 오류에는 집계 ID와 발생 단계가 포함됩니다. 실패한 계산 이전의 화면 전체를 자동 복원하는 기능은 아닙니다.
